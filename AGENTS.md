## Critical constraints

### Never manually edit generated files

- `rankless_rs/src/gen/` — auto-generated by dmove pipeline steps
- `rankless_rs/src/steps/mod.rs`, `rankless_rs/src/gen/mod.rs`, `lib.rs` `mods_as_comms!` — auto-managed by `dmove_macro`

### Always use `ET<>` entity type aliases, never raw primitives

```rust
// Wrong — silent breakage if schema changes
dm_id: u16,
arr: &[usize; 253],

// Correct
type AuthorId = ET<Authors>;
dm_id: AuthorId,
arr: &ET<MAA<Authors, CitSubfieldsArrayMarker>>,
```

`ET<E>` = `<E as Entity>::T`. `MAA<E, M>` = `<E as MarkedAttribute<M>>::AttributeEntity`. Both from `use dmove::{ET, MAA}`.

### Bootstrap constraint: step X cannot use types from `gen/X.rs`

When step X compiles, `gen/mod.rs` includes only through step X−1. Safe vs unsafe:

- `stowage.declare_iter::<B, I, E, S, M>()` — safe in same step (generates the impl)
- `stowage.get_marked_interface::<E, M, Be>()` — requires `E: MarkedAttribute<M>`; only safe if impl is in gen/(X−1) or earlier
- `stowage.ditf::<Marker, E, T>()` — requires `E: Entity`; only safe if `E` defined in gen/(X−1)
- Types defined in `gen/X.rs` cannot be imported in `steps/X.rs`

If step X needs to write data for a type it creates, move those writes to step X+1.

See `docs/architecture.md` (Metaprogramming & make pipeline) for the full build orchestration.

## Phrasing convention

**Referenced (refed) wids** = work IDs on the side being referenced (the cited papers).  
**Citing works** = the later papers doing the citing (the ones "being impacted").  
This distinction is used consistently throughout the codebase.

## Code style

### Rust

- Performance always paramount; idiomatic patterns; clear ownership semantics
- Avoid repetition and extra verbosity
- File structure order:
  1. imports (std, ext, crate)
  2. constants
  3. types
  4. macros (defs, then calls)
  5. structs → enums → traits → impls (simple, then trait) → functions → modules
- Within each category: `pub` declarations first

### Svelte

- Always TypeScript
- Component composition over prop drilling
- Extract complex logic to `src/lib/` utilities

### Python

- Type hints required

### General

- Minimal comments — code should be self-documenting
- DRY, no duplication
- Avoid new dependencies unless mature, reliable, or performance-critical
