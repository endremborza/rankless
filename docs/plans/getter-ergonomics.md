# Getter Accessor Ergonomics

## Context

`Getters` in `rankless_trees/src/interfacing.rs` exposes accessors generated by the `make_interfaces!` macro. Two accessor arms exist:

- `$f_key` (fixed-size): `pub fn foo<'a, K: UnsignedNumber>(&'a self, key: &'a K) -> &'a ET<$f_t>`
- `$v_key` (variable-size): `pub fn foo<'a, K: UnsignedNumber>(&'a self, key: K) -> &'a [VaST<$v_t>]`

## Identified bug

`$f_key` uses `key: &'a K` — the key's lifetime is unified with the return lifetime `'a`. The return is into `self.ifs.$f_key` (owned by `Getters`), so the return lifetime correctly depends on `self`. The key has no ownership relationship with the return value, so tying its lifetime to `'a` is wrong and unnecessarily restricts call sites.

Fix: separate the key lifetime.
```rust
pub fn $f_key<'a, K: UnsignedNumber>(&'a self, key: &K) -> &'a ET<$f_t>
```

## Optional cleanup (not decided)

Unify `$f_key` to take `K` by value like `$v_key` for consistency. All `ET<_>` types are `Copy`, so this is zero-cost. Trade-off:
- Removes `&` at call sites like `gets.icountry(&iid)` → `gets.icountry(iid)`
- Adds `*` at chaining call sites like `gets.icountry(cit_inst)` → `gets.icountry(*cit_inst)`

The fixed-lifetime bug is the actual correctness issue; by-value unification is cosmetic.

## Non-goal

Full entity type safety (ensuring only `ET<Institutions>` is accepted by `icountry`, not any other `u16`-based `ET<_>`) is not feasible without newtypes everywhere and is not worth pursuing.
