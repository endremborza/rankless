## How a tree is built (map for picking up)

Single query path: `TreeRunManager` worker → `TreeMakingRun::run` → `fill_calculate`
(`rankless_trees/src/part_iterator.rs:257`).

1. **Record generation** — `TMK::new(...)` builds a `PartitioningIterator` (e.g.
   `PostRefIterWrap<MinIntX<Institutions>, RefSubCiSubTByRef>`). Each `next()` walks the citation
   graph via `Peekable<Iter>` chains driven by the `opt_peek!`/`opt_next!`/`reg_peek!` macros
   (`components.rs:242`), doing several mmap getter lookups per record, emitting a flat tuple
   `(pid, (lvl0, lvl1, …, ref_wid, cit_wid))`. `pid` = work period (one of `N_PERS = 12`).

2. **Heap building** — `fill_heaps` (`part_iterator.rs:316`) allocates **16** `MinHeap`s
   (`agg_tree.rs:14`, a `BinaryHeap<Reverse<StackFr>>`) and pushes _every_ record into
   `heaps[pid]`. This is `O(N log N)` with cache-hostile access. **tlog: `got heaps`.**

3. **Sort+dedup drain** — each heap → `HeapIterator` (`agg_tree.rs:46`) pops the whole heap (another
   `O(N log N)`), `.clone()`-ing each record, dropping exact-duplicate consecutive tuples via the
   generated `SortedRecord::from_cmp`. Net effect: a **heapsort**.

4. **The fold** — `StackBasis::fold_into` → `SRecordN::fold` (generated by `def_srecs!`,
   `dmove_macro/src/lib.rs:200`). Keeps a typed stack of `IntXTree`/`DisJTree`
   (`instances.rs:39`); `update_stack` compares each record vs the previous at every level and, when
   a level's id changes, calls `Updater::update`, which merges the children's sorted citing-work
   lists (`PrepNode::update_and_get_collapsed_node` → `WVecMerger`/`ordered_calls`,
   `instances.rs:110`). Children are appended in **ascending id order** (input is sorted).
   **tlog: `got roots`.**

5. **Collapse + serialize** — `collapse()` yields the full typed tree; `fold_tree` converts it
   `Into<BufSerTree>` via `children_from_vec` (`instances.rs:397`, builds nested `HashMap<u32,…>`
   per node), `ingest_disjunct` (`io.rs:333`) merges the 12 period-trees.
   **tlog: `converted, ingested and wrote trees`.**

6. **Prune + response** — `prune` (`prune.rs:62`) keeps top-16 children/level via two `FixedHeap`s;
   `JsSerTree::from_buf` (`io.rs:399`) maps `top_source` dm_id → OA id. **tlogs: `pruned`,
   `got atts`, `converted`.**

**The macro layer** (the "convoluted setup"): `def_srecs!(7)` generates `SRecord2..7` + the
`fold`/`to_stack`/`update_stack` state machine; `impl_stack_basees!(5)` generates `StackBasis`
impls for every `(DisJ…IntX)` arrangement up to depth 5; `impl_fbarrs!` generates
`ByteFixArrayInterface` (the big_prep/big_read disk path); `derive_tree_getter` wires each `Tree1..N`
alias to a `tid` dispatch.

## Validated data

All timings via the built-in `tlog` phase timers, read from server stdout / test `--nocapture`.

### Real institution trees (`/v1/trees/institutions/<sem>?tid=0`, uncached cold compute)

| Entity   | cites | `got heaps` (heap) | `got roots` (**fold**) | `ingested` (serialize) | heap% / fold% |
| -------- | ----- | ------------------ | ---------------------- | ---------------------- | ------------- |
| Corvinus | small | 79 ms              | 72 ms                  | 25 ms                  | 43% / 39%     |
| UCL      | 12.7M | 11 486 ms          | 29 946 ms              | 138 ms                 | 27% / 72%     |
| NIH      | 13M   | 11 585 ms          | 32 109 ms              | 95 ms                  | 26% / 72%     |
| Stanford | 18M   | 15 719 ms          | **42 209 ms**          | 144 ms                 | 27% / 72%     |

> Absolute numbers were inflated by CPU contention from author-tree cache-warming arriving via an
> SSH tunnel during measurement; per-query phase **ratios** are reliable.

### Synthetic `big_tree` test (`instances.rs:1090`, 2²⁰ all-random records, no OA data)

|                       | `got heaps` | `got roots` (fold) | `ingested` |
| --------------------- | ----------- | ------------------ | ---------- |
| system malloc         | 31 ms       | **3885 ms**        | 153 ms     |
| mimalloc (prod alloc) | 37 ms       | **3946 ms**        | 73 ms      |

### What the data settled

- **Fold = #1 everywhere** (72% big real / 39% small / 90% synthetic), and **compute-bound, not
  allocation-bound** — mimalloc moved the fold 0% (3885→3946 ms). ⇒ an arena/pool allocator will
  **not** help; reduce per-record CPU work instead.
- **Heap = #2 and real.** The synthetic test (all-distinct random) made the heap look like 0.7%, but
  on clustered real data it's **26–43%** (11–16 s on big institutions). Reason: the heap sorts _all
  N_ records regardless of clustering with cache-hostile `BinaryHeap` access, while the fold gets
  relatively cheaper as data clusters.
- **Serialization (HashMap) negligible on real data** (95–144 ms ≈ 0.3%). The 153 ms synthetic
  figure was the all-distinct worst case. ⇒ the HashMap→sorted-Vec refactor is **not** worth its
  blast radius. `JsSerTree::from_buf` is sub-millisecond — ignore the `//TODO: wasteful`.

## Implementation plan

### #2 — Heap → sort ✅ DONE (2026-06-20)

**Implemented** in `rankless_rs/src/agg_tree.rs`: `MinHeap` is now a lazily `sort_unstable`'d `Vec`
(`new`/`push`/`pop`/`from_iter` API unchanged, so `fill_heaps`, `read_big_calculate`, and
`HeapIterator` are untouched). Validation:

- **Micro-bench** (`/tmp/heapbench.rs`, 30M representative 5-tuples): `BinaryHeap` push+drain 17 113 ms
  vs `Vec`+`sort_unstable` 1 386 ms = **12.35×** (the binary-heap _drain_ is the killer: 16.7 s vs
  34 ms to walk a sorted Vec). Even bigger than the original 2–3× estimate.
- **Correctness**: `big_tree` test passes with a **byte-identical tree** (`lc 1048576, sc 1048434,
ts Some(16735219)`); `cargo fmt --check` + `cargo check --workspace` clean.
- **Not yet measured on the live server** — the running binary predates this change; needs a
  rebuild + restart (deferred: server was busy piping caches to alpha). Expect `got heaps` on big
  institutions to fall from ~11–16 s toward ~1.5–2 s.

Original notes (for reference):

The `MinHeap` is only ever **fully drained in ascending order** (`fill_calculate` /
`read_big_calculate`) — it's a heapsort. `StackFr: Ord` already holds (it's in the `run`
where-clause), and `work_set.rs:86` already uses `sort_unstable` for the same kind of job.

Localized change in `rankless_rs/src/agg_tree.rs` only — **no call-site changes** (both `fill_heaps`
and `read_big_calculate` use `MinHeap::new`/`push` + `From<MinHeap> for Option<HeapIterator>` which
calls `pop()`). Replace the `BinaryHeap<Reverse<T>>` with a lazily-sorted `Vec`:

```rust
pub struct MinHeap<T> { data: Vec<T>, sorted: bool }

impl<T: Ord> MinHeap<T> {
    pub fn new() -> Self { Self { data: Vec::new(), sorted: false } }
    pub fn push(&mut self, e: T) { self.data.push(e); }     // O(1), no sift
    pub fn pop(&mut self) -> Option<T> {
        if !self.sorted {
            // descending sort so Vec::pop() yields ascending (smallest last)
            self.data.sort_unstable_by(|a, b| b.cmp(a));
            self.sorted = true;
        }
        self.data.pop()
    }
    pub fn from_iter<I: Iterator<Item = T>>(iter: I) -> Self {
        Self { data: iter.collect(), sorted: false }
    }
}
```

- Drop the `use std::collections::BinaryHeap` + `Reverse` imports.
- `From<MinHeap<…>> for Option<HeapIterator<…>>` and `HeapIterator::next` are unchanged (they call
  `pop()`), so the dedup semantics are identical (ascending drain + consecutive `from_cmp`).
- Optional follow-up (separate, minor): the per-pop `.clone()` in `HeapIterator::next`
  (`agg_tree.rs:109`) can be removed by iterating the sorted `Vec` by reference. Not required for the
  win.
- **Reserve capacity** (small extra win): in `fill_heaps`, pre-size each period's `Vec` — citing
  counts are available via `gets.wccount(wid)`; or just `Vec::with_capacity` a rough estimate.

**Measure:** re-run a big institution (see [reproduce](#reproducing-the-profile)); expect `got heaps`
to drop ~2–3×.

### #1 — Fold per-record cost (the 72%) — **perf'd 2026-06-20**

`perf record -g --call-graph=dwarf` on the `big_tree` binary (built under the new `[profile.profiling]`).
The single hottest fold function is **`PrepNode::update_and_get_collapsed_node` — 25% self-time**
(the per-node merge; `ordered_calls`/`WVecMerger` are inlined into it). Source-line annotation of
that function:

| Inside the merge                               | source                                   | ≈ share of fn | optimization                                          |
| ---------------------------------------------- | ---------------------------------------- | ------------- | ----------------------------------------------------- |
| Vec pushes of merged source/target arrays      | `alloc …/vec/mod.rs` (`.add`)            | ~33%          | inherent; pre-reserve                                 |
| `ordered_calls` comparison state machine       | `muwo_search/src/merging.rs:147,160,170` | ~12%          | **F1** fast-path / hand-roll                          |
| **slice bounds-checks**                        | `core …/index.rs:272`, `range.rs:772`    | ~11%          | **elide (get_unchecked)** — in-bounds by construction |
| `WVecPair::add` / `WVecMerger::right_map` copy | `instances.rs:104,141,142`               | ~10%          | **F1**                                                |

Other notable self-time (whole process): `clear_page_erms` (kernel page-zeroing) 14.6% +
malloc/free/page-fault ~6% ⇒ **~20% allocation/page-fault** from the ~1M-node worst-case tree —
_kernel_ page-zeroing, not user-space allocator (matches the mimalloc no-op); reduce via **fewer/larger
node allocations (F4)**, not a faster allocator. ~20% more is **synthetic-test scaffolding** (`rand_chacha`
7.2% generating records, `Getters::fake` 3.5%, `format!` ~8% building fake att labels) — _not_ the
fold; a real-server profile removes it.

Prioritized fold work (most targeted first):

- **F1 — trivial/small-merge fast path** in `update_and_get_collapsed_node` (`instances.rs:152`):
  when one side is empty (common right after `reset`) or single-element, bypass `WVecMerger` +
  `ordered_calls` and move/`extend_from_slice` directly. Hits the ~12% comparison loop + ~10% copy +
  per-merge setup. Biggest targeted win, esp. for high-distinctness levels.
- **Bounds-check elision** in `WVecPair::add` (`instances.rs:99`) and `WVecMerger::common_map`
  (`instances.rs:125`): the `targets[ind]` / `targets[a..b]` accesses are in-bounds by construction
  (counts come from the `WorkWInd` source). ~11%, low risk, isolated. **Easiest concrete win.**
- **F4 — node-construction allocation churn**: pool/reuse child `Vec`s or pre-`reserve` so the tree
  build stops first-touching new pages (the ~20% page-zeroing). Helps the worst case most.
- **F3** (per-record enum churn) and **F2** (merge dispatch) did **not** stand out — `ordered_calls`
  inlined fine (monomorphized), so deprioritize.

**Caveat:** the synthetic test is all-distinct ⇒ every record triggers a full-depth unwind (4 merges)
and maximal node count, over-weighting both the merge _count_ and the allocation share. Re-validate
F1 + bounds-elision on a real uncached institution query after implementing.

### #3 — Cleanups (trivial)

- Cache `TMK::get_spec()` / breakdowns per request — currently rebuilt (with `String` allocs) 3×
  per query (`part_iterator.rs:457,466,493`; `to_bds` in `components.rs:1584`).
- `MAX_PARTITIONS` 16 → `N_PERS` (12) (`part_iterator.rs:40`): 4 heaps are always empty.
- Silence the 11×/query `"parition-heap is none at roots len N"` log (`part_iterator.rs:284`) — also
  fix the `parition` typo. It's printed on every empty trailing partition.

 "import sys,json;[print(e['semanticId'],e['citations']) for e in json.load(sys.stdin)]"

`prof()` helper used last session (filters tlog by the query's exact entity id; `LC_ALL=C` avoids a
locale decimal-comma bug; institutions/authors are uncached → full fold):

```bash
prof() {
  local sem=$1 START=$(wc -l < /tmp/rl-server.log)
  local t=$(LC_ALL=C curl -s -o /tmp/resp.json -w "%{time_total}" \
            "http://127.0.0.1:3038/v1/trees/institutions/$sem?tid=0")
  local region=$(tail -n +$((START+1)) /tmp/rl-server.log)
  local id=$(echo "$region" | grep -oE "institutions\([0-9]+" | grep -oE "[0-9]+" | head -1)
  printf ">>> %-22s id=%s wall=%ss\n" "$sem" "$id" "$t"
  echo "$region" | grep -E "institutions\($id:" \
    | grep -E "got heaps|got roots|ingested|loaded and sent" | sed 's/^/    /'
}
prof su ; prof nih ; prof ucl     # large fresh (uncached) institutions
```

## Caveats for next session (post-pipeline-rerun)

- **dm_ids change** on every pipeline rerun; the ids in the tables (su=4644, nih=12193, ucl=9936,
  Corvinus=18250) are stale. **sem-ids** (`harvard-university`, `su`, `nih`, `ucl`, …) are stable —
  use those.
- **Tree cache is cleared/rebuilt** by the rerun, so institution/author queries are cold again
  (good for profiling). `$OA_ROOT/cache/{countries,sources,subfields,hit-papers}` get repopulated;
  authors/institutions are computed on demand.
- Cacheable threshold: `cites ≥ CACHEABLE_FROM (10k)` (`consts.rs`) → big entities cache after first
  hit; re-query a _fresh_ big entity to re-measure cold.
- Watch for **contention**: cache-warming traffic (author trees, `year=Some(1950)`, multiple tids)
  via SSH tunnel / `live_monitoring` competes for the 16-thread tree pool and inflates absolute
  timings. Profile when idle, or rely on per-query ratios.
