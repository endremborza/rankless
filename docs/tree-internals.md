# Tree construction internals

How `rankless_trees` builds a hierarchical tree for `/v1/trees/...` — the per-query work behind
every breakdown. Single query path: `TreeRunManager` worker → `TreeMakingRun::run` →
`fill_calculate` (`rankless_trees/src/part_iterator.rs`).

1. **Record generation** — `TMK::new(...)` builds a `PartitioningIterator` (e.g.
   `PostRefIterWrap<MinIntX<Institutions>, RefSubCiSubTByRef>`). Each `next()` walks the citation
   graph via `Peekable<Iter>` chains driven by the `opt_peek!`/`opt_next!`/`reg_peek!` macros
   (`components.rs`), doing several mmap getter lookups per record, emitting a flat tuple
   `(pid, (lvl0, lvl1, …, ref_wid, cit_wid))`. `pid` = work period (one of `N_PERS = 12`).

2. **Heap building** — `fill_heaps` allocates one `MinHeap` per period (`agg_tree.rs`; the array
   is sized `MAX_PARTITIONS`) and pushes _every_ record into `heaps[pid]`. `MinHeap` is a lazily
   `sort_unstable`'d `Vec` (push is O(1); the sort happens on first drain). **tlog: `got heaps`.**

3. **Sort+dedup drain** — each heap → `HeapIterator` (`agg_tree.rs`) drains in ascending order,
   dropping exact-duplicate consecutive tuples via the generated `SortedRecord::from_cmp`. Net
   effect: a sort + dedup of all records per period.

4. **The fold** — `StackBasis::fold_into` → `SRecordN::fold` (generated by `def_srecs!`,
   `dmove_macro/src/lib.rs`). Keeps a typed stack of `IntXTree`/`DisJTree` (`instances.rs`);
   `update_stack` compares each record vs the previous at every level and, when a level's id
   changes, calls `Updater::update`, which merges the children's sorted citing-work lists
   (`PrepNode::update_and_get_collapsed_node` → `WVecMerger`/`ordered_calls`, `instances.rs`).
   Children are appended in **ascending id order** (input is sorted). **tlog: `got roots`.**

5. **Collapse + serialize** — `collapse()` yields the full typed tree; `fold_tree` converts it
   `Into<BufSerTree>` via `children_from_vec` (`instances.rs`, builds nested `HashMap<u32,…>` per
   node), `ingest_disjunct` (`io.rs`) merges the 12 period-trees.
   **tlog: `converted, ingested and wrote trees`.**

6. **Prune + response** — `prune` (`prune.rs`) keeps the top children per level via two
   `FixedHeap`s; `JsSerTree::from_buf` (`io.rs`) maps each `top_source` dm_id → OA id.
   **tlogs: `pruned`, `got atts`, `converted`.**

## The macro layer

The "convoluted setup": `def_srecs!(7)` generates `SRecord2..7` + the `fold`/`to_stack`/
`update_stack` state machine; `impl_stack_basees!(5)` generates `StackBasis` impls for every
`(DisJ…IntX)` arrangement up to depth 5; `impl_fbarrs!` generates `ByteFixArrayInterface` (the
`big_prep`/`big_read` disk path); `derive_tree_getter` wires each `Tree1..N` alias to a `tid`
dispatch.
