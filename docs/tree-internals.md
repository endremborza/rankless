# Tree construction internals

How `rankless_trees` builds a hierarchical tree for `/v1/trees/...` — the per-query work behind
every breakdown. Single query path: `TreeRunManager` worker → `TreeMakingRun::run` →
`fill_calculate` (`rankless_trees/src/part_iterator.rs`).

1. **Record generation** — `TMK::new(id, gets, works)` builds a `PartitioningIterator` (e.g. `PostRefIterWrap<MinIntX<Institutions>, RefSubCiSubTByRef>`) over the root's works whose ids fall in `works` (`within`: a binary search into the root's id-sorted work list). Each `next()` walks the citation graph via `Peekable<Iter>` chains driven by the `opt_peek!`/`opt_next!`/`reg_peek!` macros (`components.rs`), doing several resident-column lookups per record, emitting a flat tuple `(lvl0, lvl1, …, ref_wid, cit_wid)`.

2. **Year walk** — `walk_years` goes through the periods newest first and through each period's years oldest first. Works are numbered by publication year (`a1_entity_mapping`), so a year's works are one run of ids (`Getters::year_works`). A year's records go into the open run's `MinHeap` (`agg_tree.rs`, a lazily `sort_unstable`'d `Vec`: push is O(1), the sort happens on first drain), and the run is folded (steps 3–5) once it holds `RUN_RECORDS` records and at its period's end, so a build holds one run's records rather than all of them. **tlog: `got heaps`** (record generation over all runs).

3. **Sort+dedup drain** — a run's heap → `HeapIterator` (`agg_tree.rs`) drains in ascending order, dropping exact-duplicate consecutive tuples via the generated `SortedRecord::from_cmp`. Duplicates share their cited work, so they fall in one run.

4. **The fold** — `StackBasis::fold_into` → `SRecordN::fold` (generated by `def_srecs!`,
   `dmove_macro/src/lib.rs`). Keeps a typed stack of `IntXTree`/`DisJTree` (`instances.rs`);
   `update_stack` compares each record vs the previous at every level and, when a level's id
   changes, calls `Updater::update`, which merges the children's sorted citing-work lists
   (`PrepNode::update_and_get_collapsed_node` → `WVecMerger`/`ordered_calls`, `instances.rs`).
   Children are appended in **ascending id order** (input is sorted). **tlog: `got roots`** (fold, collapse and merge over all runs).

5. **Collapse + merge** — `collapse()` yields the run's typed tree; `fold_tree` converts it `Into<BufSerTree>` via `children_from_vec` (`instances.rs`, builds nested `HashMap<u32,…>` per node) and `ingest_disjunct` (`io.rs`) adds it into the cumulative tree. A cited work's records all fall in one run and the counts of disjoint cited works add, so however a period splits into runs, merging them oldest first gives the tree one fold of the period would (`year_runs_merge_into_the_period_trees`); a top source tie goes to the newer period, then the lower work id. After each period the cumulative tree is that period's: it is pruned and written to the cache, and answered when it is the requested one. **tlog: `converted, ingested and wrote trees`** (the writes), then one line per tree: `N records in R runs, the largest L`.

6. **Prune + response** — `prune` (`prune.rs`) keeps the top children per level via two
   `FixedHeap`s; `JsSerTree::from_buf` (`io.rs`) maps each `top_source` dm_id → OA id.
   **tlogs: `pruned`, `got atts`, `converted`.**

## The macro layer

The "convoluted setup": `def_srecs!(7)` generates `SRecord2..7` + the `fold`/`to_stack`/
`update_stack` state machine; `impl_stack_basees!(5)` generates `StackBasis` impls for every
`(DisJ…IntX)` arrangement up to depth 5; `derive_tree_getter` wires each `Tree1..N` alias to a
`tid` dispatch.
